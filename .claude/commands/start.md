Ты стартуешь новую сессию по этому проекту. Введи себя в курс дела и выдай краткий бриф. Выполни шаги **молча** (без комментариев по ходу), затем выведи только итоговый бриф.

## Что прочитать

1. **Правила и архитектура** — @CLAUDE.md полностью. Это главный источник: стек, блочная система (`type` ↔ `componentsMap` ↔ компонент), стилевые конвенции, предупреждение про `content.config.ts`, список TODO.
2. **Память проекта** — прочитай свой индекс памяти `MEMORY.md` и **все** файлы из каталога памяти этого проекта (`user-*`, `project-*`, `nda-*`, `lang-*` и любые новые). Это факты, которых нет в коде: кто пользователь, цель, NDA/приватность, язык общения.
3. **Команды** — просмотри `.claude/commands/*.md` (поле `description` у каждой), чтобы знать доступный инструментарий: `/new-section`, `/new-page`, `/new-post`, `/content-check`, `/start`.
4. **Скиллы** — просмотри `.claude/skills/*/SKILL.md` (frontmatter `name`/`description`), чтобы знать, когда они применимы (`section-block`).
5. **Состояние репозитория** — выполни: текущая ветка, `git status --short`, последние 3 коммита (`git log --oneline -3`). Так поймёшь, что в работе прямо сейчас.

## Что вывести (бриф)

Коротко, по-русски, в таком порядке:

- **Кто и зачем** — 1–2 строки: пользователь (из памяти) + цель проекта.
- **Ключевые правила** — язык общения (русский), NDA/приватность (не анонсировать публично), не коммитить/пушить без просьбы.
- **Архитектура в двух словах** — блочная система: контент в `content/**/*.json` (`body[]`), маппинг `type` → компонент в `app/blocks/componentsMap.ts`. Напомни про запрет на `content.config.ts` с `type: 'page'`.
- **Инструментарий** — список доступных команд (одной строкой) и скиллов.
- **Состояние** — ветка, кратко незакоммиченные изменения, открытые задачи из раздела TODO в CLAUDE.md (только незакрытые).
- **Готов к работе** — закончи вопросом, с какой задачи начинаем.

Держи бриф компактным (≈15–20 строк). Не дублируй полностью содержимое файлов — только выжимку, достаточную, чтобы сразу приступить к делу.
