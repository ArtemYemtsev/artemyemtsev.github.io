---
description: Перевести/синхронизировать контент-страницу по всем локалям (en/ru/uk)
argument-hint: <slug | index> [исходная-локаль]
---

Перенеси страницу на все языки сайта, сохранив структуру блоков. Аргументы: `$ARGUMENTS`
(первый — `slug` страницы относительно папки локали, например `about`, `services`, или `index` для главной; второй — необязательная исходная локаль, по умолчанию `en`).

Контекст мультиязычности — см. @CLAUDE.md (раздел «Мультиязычность»). Локали: `en` (основной), `ru`, `uk`. Контент лежит в `content/<locale>/<slug>/index.json` (для главной — `content/<locale>/index.json`).

Шаги:
1. Прочитай исходный файл `content/<src-locale>/<slug>/index.json`. Если не указан — `en`.
2. Для каждой **другой** локали (`ru`, `uk` при источнике `en`):
   - Создай/обнови `content/<locale>/<slug>/index.json` с **идентичной структурой** блоков.
   - **Переводи только текстовые поля**: `title`, `description`, и в блоках — `title`, `subtitle`, `text` (включая HTML-разметку внутри `text` — переводи текст, теги оставляй), `content`, подписи в списках.
   - **НЕ трогай** служебные поля: `type`, `icon`, `link`, `order`, `draft`, имена технологий/брендов (`Vue.js`, `Figma` и т.п.), URL, email.
   - Имя-бренд автора локализуй по языку: `Artem Yemtsev` → `Артём Емцев` (ru) / `Артем Ємцев` (uk).
3. Сверь, что во всех локалях одинаковый набор блоков и ключей (рассинхрон структуры = разное поведение страниц по языкам).
4. Покажи краткий дифф: какие поля переведены, что осталось без изменений.
5. Предложи `npm run generate` и проверку `/<locale>/<slug>` для всех языков.

Если переводишь markdown-пост блога — действуй аналогично с `content/<locale>/blog/<slug>.md`: переводи фронтматтер (`title`, `description`) и тело, код/команды в бэктиках не трогай.
